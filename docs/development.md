# Development guide

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Python | 3.11+ | Developed on 3.13 |
| Node.js | 20+ | Developed on 22 |
| PostgreSQL | 16+ | With the `pgvector` extension available |

```bash
# macOS
brew install postgresql@17 pgvector
brew services start postgresql@17
createdb atlas
createdb atlas_test
```

`pgvector` is enabled by the first migration, so no manual `CREATE EXTENSION` is needed —
only the extension files must be installed.

## Backend

```bash
cd backend
python3 -m venv .venv
./.venv/bin/pip install -e ".[dev]"

cp .env.example .env
# Generate a real key:
python3 -c "import secrets; print('SECRET_KEY=' + secrets.token_urlsafe(48))"

./.venv/bin/alembic upgrade head
./.venv/bin/uvicorn atlas.main:create_app --factory --reload
```

API on <http://localhost:8000>. Interactive docs at `/docs` (disabled in production).

Note the `--factory` flag: `atlas.main` deliberately exposes `create_app()` rather than a
module-level `app`, so importing the module has no side effects and tests can build an
application with their own settings.

### Tests

```bash
./.venv/bin/pytest              # whole suite
./.venv/bin/pytest -k auth      # one area
./.venv/bin/pytest -x -q        # stop at first failure
```

Tests run against `atlas_test`, which is migrated down to base and back up once per session.
Each test truncates the tables it touched, so tests cannot depend on each other's data.

Point the suite elsewhere with `TEST_DATABASE_URL`.

### Lint and types

```bash
./.venv/bin/ruff check . --fix
./.venv/bin/ruff format .
./.venv/bin/mypy atlas
```

All three must be clean before a commit.

### Migrations

```bash
./.venv/bin/alembic revision --autogenerate --rev-id 0002 -m "papers and chunks"
./.venv/bin/alembic upgrade head
./.venv/bin/alembic downgrade -1
```

Revision ids are sequential (`0001`, `0002`, …) rather than random hashes, so the migration
directory reads in order.

**Always read an autogenerated migration before applying it.** Autogenerate does not detect
everything — extensions, index method changes, and data backfills have to be written by hand.
Verify `downgrade()` actually reverses `upgrade()`; the test suite runs a full
`downgrade base` → `upgrade head` cycle, so a broken downgrade fails the suite.

Every model must be imported in `atlas/models/__init__.py`. Autogenerate compares against
`Base.metadata`, and a model nothing imports is invisible to it — the symptom is a migration
that silently drops the table.

## Frontend

```bash
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

App on <http://localhost:3000>.

```bash
npx tsc --noEmit    # type-check
npm run lint
npm run build       # type-checks and prerenders; catches server/client boundary errors
```

`npm run build` is the real gate. It prerenders every static route, so mistakes that only
appear during server rendering — a client hook in a server component, a component that throws
without a browser — surface there and not in `dev`.

## Conventions

**Backend**

- Business rules live in `services/`, not in route handlers. A service must be callable from a
  worker or a script with no HTTP request present.
- Raise errors from `core/errors.py`. Never construct an error response by hand.
- `detail=` on an error is for the logs; `message` is what the user reads. Detail is never
  serialised into a response.
- Nothing reads `os.environ` outside `core/config.py`.
- Never log credentials, tokens, or document contents.

**Frontend**

- Server components by default. Add `"use client"` only when a component needs state, effects,
  or event handlers.
- Style with design tokens (`text-ink-muted`, `bg-surface`), never raw colours. A hard-coded
  hex will be wrong in one of the two themes.
- Interactive elements need a visible focus state, an accessible name, and keyboard operation.
- Every async surface needs all four states: loading, empty, error, and content.

**Commits**

Conventional prefixes: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`. The subject
says what changed; the body says why, when why is not obvious.

## Troubleshooting

**`relation "users" does not exist` in tests** — the test database has not been migrated.
Confirm `atlas_test` exists; the session fixture migrates it automatically.

**`database_url must use the postgresql+asyncpg:// scheme`** — the DSN is missing the async
driver. Atlas is async end to end and will not run on `psycopg2`.

**Autogenerate produces an empty migration** — the model is not imported in
`atlas/models/__init__.py`.

**Frontend requests fail with a CORS error** — `CORS_ORIGINS` in `backend/.env` must exactly
match the frontend origin, scheme and port included. A wildcard is not valid here: cookie
authentication requires `allow_credentials`, and the two are mutually exclusive.

**Signed in but every request 401s** — check that `NEXT_PUBLIC_API_URL` and `CORS_ORIGINS`
agree, and that the browser is not blocking third-party cookies for `localhost`.
